# Валидация ввода пользователя на ask-нодах

**Дата:** 2026-04-09
**Статус:** Утверждён

## Цель

Добавить рантайм-валидацию ввода пользователя бота на нодах `ask_text` и `ask_keyboard`. Правила в стиле Laravel, комбинируемые, с кастомными сообщениями ошибок на каждое правило. При ошибке — бот автоматически показывает сообщение и переспрашивает.

## Структура данных

### Валидация в data ноды

Поле `validation` — массив правил. Каждое правило — объект `{ name, params?, message? }`.

```json
{
  "type": "ask_text",
  "data": {
    "text": "Введите ваш email",
    "validation": [
      { "name": "required", "message": "Поле обязательно для заполнения" },
      { "name": "email" },
      { "name": "max", "params": [255] }
    ]
  }
}
```

- `name` — название правила (строка)
- `params` — массив параметров правила (опционально)
- `message` — кастомный текст ошибки (опционально)
- Если `validation` отсутствует или пустой массив — нода работает без валидации

### Дефолтные сообщения бота

Хранятся в поле `config` модели `Bot`:

```json
{
  "validation_messages": {
    "required": "Пожалуйста, введите значение",
    "email": "Введите корректный email",
    "numeric": "Значение должно быть числом"
  }
}
```

### Приоритет сообщений об ошибке

1. `message` на конкретном правиле в ноде — высший приоритет
2. `bot.config.validation_messages[rule_name]` — дефолт бота
3. Системный дефолт (хардкод) — fallback

## Набор правил

| Правило    | Параметры       | Системный дефолт                          |
|------------|-----------------|-------------------------------------------|
| `required` | —               | Пожалуйста, введите значение              |
| `string`   | —               | Значение должно быть текстом              |
| `numeric`  | —               | Значение должно быть числом               |
| `integer`  | —               | Значение должно быть целым числом         |
| `email`    | —               | Введите корректный email                  |
| `url`      | —               | Введите корректный URL                    |
| `phone`    | —               | Введите корректный номер телефона         |
| `min`      | `[value]`       | Минимальное значение: {0} / Минимальная длина: {0} символов |
| `max`      | `[value]`       | Максимальное значение: {0} / Максимальная длина: {0} символов |
| `between`  | `[min, max]`    | Значение должно быть от {0} до {1}       |
| `in`       | `[...values]`   | Допустимые значения: {0}                  |
| `regex`    | `[pattern]`     | Значение не соответствует формату         |
| `date`     | —               | Введите корректную дату                   |

- `{0}`, `{1}` — подставляются из `params` правила
- Для `min`/`max` текст зависит от контекста: если в том же массиве есть `numeric`/`integer` — "значение", иначе — "длина символов"
- Маппинг на Laravel-правила при кодогенерации: `{ name: "max", params: [255] }` → `"max:255"`

## Поведение в рантайме

1. Пользователь отправляет ответ на `ask_*` ноду
2. Правила проверяются **последовательно**, в порядке массива
3. Первое непрошедшее правило — проверка прекращается
4. Бот отправляет **два сообщения**: текст ошибки, затем повтор текста вопроса
5. Бот ждёт новый ввод — цикл повторяется
6. Когда ввод проходит все правила — переход по связи дальше

**Без лимита попыток.** Для сложных сценариев (N попыток → эскалация) автор бота использует блок Условие и ручное ветвление.

## UI: секция валидации в панели свойств ноды

Появляется в формах `AskTextForm` и `AskKeyboardForm`, под основными полями.

- **Collapsible секция** "Валидация" — свёрнута по умолчанию
- Бейдж с количеством правил рядом с заголовком: `Валидация (3)`
- Каждое правило — **карточка**:
  - Название правила
  - Поля параметров (если есть у правила)
  - Поле "Сообщение" (опциональное, placeholder = текст из дефолтов бота или системный)
  - Кнопка удаления `[✕]`
- **Drag-and-drop** для изменения порядка правил
- Кнопка **"+ Добавить правило"** — dropdown с группами:
  - Общие: required
  - Тип: string, numeric, integer, date
  - Формат: email, url, phone, regex
  - Диапазон: min, max, between, in
- Уже добавленные правила не показываются в dropdown

## UI: настройка дефолтных сообщений бота

Страница в настройках бота — секция **"Сообщения валидации"**.

- Список всех 13 правил, каждое — текстовое поле
- Placeholder = системный дефолт (виден когда поле пустое)
- Если поле пустое — используется системный дефолт
- Поддержка `{0}`, `{1}` — подсказка под полями для правил с параметрами

Хранение: `bot.config.validation_messages` (JSON в существующем поле `config`).

## UI: индикация на канвасе

На нодах `ask_text` / `ask_keyboard` — **иконка щита** в углу ноды, отображается если у ноды есть хотя бы одно правило валидации.

## Вне скоупа

- Лимит попыток ввода (решается через Условие + ручное ветвление)
- Валидация на связях (edges)
- Серверная валидация структуры graph при сохранении (отдельная задача)
- Асинхронная валидация (проверка через API)
